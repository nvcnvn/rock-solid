# Build checklist: phases 1 to 6

Phases 1 to 5 of the [roadmap](design.md#roadmap-and-open-questions) produce nothing a user can run; phase 6, the file frontend, is the first usable product. This list breaks phases 1 to 6 into building blocks that can each be reviewed on their own. An item is a **component** (a state machine or driver), a **lib** (a dependency or a shared encoding) or a **test** (a suite, harness or measurement). Each one names its package under `internal/` and what must hold before it is reviewed. The design lives in [design.md](design.md); items link to it rather than restate it. Each item ends with its test plan: what its tests must show, by test name. An item's open question is settled in the design before the item is reviewed.

Items are in build order within a phase. An item can start once the items it uses are reviewed.

**Every item, before review**

- `scripts/lint.sh` passes, and sans-IO packages pass the sans-IO analyzer ([Modularity](design.md#modularity-sans-io-core-pluggable-drivers)).
- Hot-path benchmarks report zero allocations per operation.
- Unit tests feed events and assert on actions, with no mocks; every decoder has a fuzz test.
- New invariants are registered with the simulator's checker in the same change.
- `scripts/seeds.sh` passes, with every new seeded property test in its list, and every failing seed found so far is a regression test.
- `docs/design.md` matches the code, and `docs/tech-debts.md` lists any pin or workaround.
- A change to a protocol that a model under `models/` covers updates that model and, where they change, its negative variants and their rows in `scripts/model-rules.tsv` in the same change, and `scripts/models.sh ci` passes; the model gate (`scripts/model-gate.sh`) holds each commit to it. A protocol no model covers gets its model before its code, and code that has a model is held to it ([From spec to code](design.md#testing-strategy)). `deep` runs come at milestones, and no item waits for one.

## Phase 1: sans-IO core and simulator

**Tooling**

- [x] **Module, toolchain and lint** (lib). One Go module pinned with `toolchain go1.27.0`, and `scripts/lint.sh` runs `gofmt`, `go vet`, the sans-IO analyzer, `staticcheck`, `govulncheck` and a dependency license check under that toolchain, whatever Go is installed locally ([tech debt](tech-debts.md#version-pin-go-toolchain-1270-and-lint-tools)). `spikes/` and `studies/` are never linted. Review when a planted fault of each kind fails the script and names its cause. Tests: none by name; the script is run on every commit, and a `govulncheck` that cannot reach the network warns and skips rather than failing.
- [x] **Sans-IO analyzer** (lib, `tools/sansio`). A `go/analysis` pass that `scripts/lint.sh` runs through `go vet -vettool` over the module, enforcing the [rules for state machines](design.md#modularity-sans-io-core-pluggable-drivers) by package class: sans-IO, data path, or unchecked. Review when it rejects in `internal/core` a planted `range` over a map, `time.Now`, `go` statement, channel, `sync` import and global `math/rand` draw, accepts them in a test file, and in the data-path packages accepts the goroutine and `sync` but rejects the map `range`, `time.Now`, the channel and free-form logging. Tests: every planted finding in `tools/sansio/testdata` is reported with its message, and a clean package reports nothing (`TestAnalyzer`); import paths fall into the right class, a path component matching rather than a string prefix (`TestClassify`).

**Foundations** (`internal/core`)

- [x] **Event and Action types** (component). `Tick`, `IOID`, `TimerID`, `NodeID`, `Context`, `Event`, `Action` as in [Modularity](design.md#modularity-sans-io-core-pluggable-drivers). `DiskWrite` takes a vector of buffers, so group commit writes producers' buffers in place. Review when the three driver-contract rules are expressible: data travels only as `IOBuf` handles, control messages of 256 bytes or less go inline, and a `PeerLost` fails a peer's outstanding requests. Tests: a 257-byte inline message is refused with its length (`TestInlineMsgLimit`); ticks convert to and from durations (`TestTick`); pool exhaustion is a matchable error carrying requested and available bytes (`TestPoolExhaustedError`); building an event and appending actions allocates nothing (`TestEventAndActionAllocateNothing`).
- [x] **Buffer pool interface** (component; heap pool in `internal/sim`). `IOBuf` handles of a slot and a generation, from a pool of explicit size; a fresh buffer is poisoned, never zeroed or left with its last owner's bytes; a buffer a failed device may still write into can be quarantined, never handed out again. Review when an exhausted pool is an error the caller handles, never a panic or a heap fallback, and a stale handle is caught. Tests: allocation, rounding to blocks, slot limits, stale and freed handles panicking and exhaustion as an ordinary outcome (`TestPool`); fresh buffers carry the poison byte (`TestAllocPoisons`); the pool matches a first-fit model with quarantines (`TestPoolIsFirstFit`); a pool refuses a region it cannot address (`TestNewPoolRefusesRegionsItCannotAddress`).
- [x] **Seeded RNG** (lib). `math/rand/v2` with a seeded PCG or ChaCha8 source per state machine, and a golden stream checked in, since a change to the generator breaks the replay of every recorded seed. Tests: one seed gives one stream across every draw kind (`TestRandSameSeedSameStream`); the first draws for seed 0 match the checked-in values (`TestRandGoldenStream`); a fork is deterministic and differs from its parent (`TestRandFork`); bounded draws stay in range and are unbiased (`TestRandBounds`); a seeded shuffle repeats (`TestRandShuffle`).
- [x] **IDs and hashing** (lib). Inode ID and 128-bit `ChunkID` packing and the PG hash (`xxh3_64`, seed 0, top bits) from the [key layout](design.md#metadata-layer-metastore) and [placement groups](design.md#data-layer-chunkstore). Both are frozen disk format: `internal/core/testdata/chunk_id_golden.txt` is never edited. Tests: packing round-trips and refuses out-of-range fields (`TestInodeIDPacking`, `TestChunkIDPacking`); an offset past 16 PiB is an error (`TestChunkIndexOf`); a PG count is a non-zero power of two (`TestPGCount`); doubling the PG count maps PG p to 2p or 2p + 1 (`TestPGSplitKeepsRangesContiguous`); every golden row matches and there are exactly 10 (`TestChunkIDGoldenVectors`); `BenchmarkChunkHash`.
- [x] **CRC32C** (lib). `hash/crc32` with the Castagnoli table, stored little-endian. Tests: the RFC 3720 appendix B.4 vectors (`TestCRC32CVectors`); continuing a CRC at any split point equals the one-shot CRC (`TestCRC32CIncremental`); `BenchmarkCRC32CBlock`.
- [x] **Lease clocks in the context** (component). `Context.Raw`, the time on `CLOCK_MONOTONIC_RAW` in ticks beside `Now` on `CLOCK_BOOTTIME`, and a `Resumed` event kind, as in [Modularity](design.md#modularity-sans-io-core-pluggable-drivers): every lease is counted on both clocks and a holder ends its leases on `Resumed` ([Epoch changes](design.md#epoch-changes-and-failure-detection)). Neither clock is derived from the other, and a machine that holds no lease ignores `Resumed`. Review when a test can set `Now` and `Raw` apart and the simulated disk's harness and every existing machine's tests set both. Tests: the context carries two independent clocks (`TestContextCarriesTwoClocks`); `Resumed` needs no other field (`TestResumedNeedsNoOtherField`); peer deadlines are on `Now` alone (`TestPeerDeadlinesIgnoreRaw`); group commit's trace is the same whatever `Raw` holds, and `Resumed` keeps its rounds in flight (`TestRawClockChangesNoTrace`, `TestResumedKeepsRoundsInFlight`).
- [x] **Peer requests** (component). Outstanding requests per peer with their deadlines and buffers: a timeout keeps the request and its buffer, since the driver may still hold it, `PeerLost` fails them all and returns their buffers, and a timer is matched to its current request and deadline, so a stale one is ignored. Tests: a send emits the message then its timer, and a duplicate ID or timer panics (`TestSendEmitsMessageThenTimer`, `TestSendInFlightIDOrTimerPanics`); `PeerLost` fails every request to that peer only (`TestPeerLostFailsEveryRequestToThatPeer`); a timeout keeps the buffer until a reply or `PeerLost` (`TestTimeoutKeepsTheBuffer`, `TestTimedOutRequestIsFailedByPeerLost`, `TestTimerReusedAfterTimeout`); a completed request reports nothing more (`TestCompletedRequest`); a stale timer is matched to the current request (`TestStaleTimerIsMatchedToTheCurrentRequest`); send and complete allocate nothing (`TestSendAndCompleteAllocateNothing`, `BenchmarkSendComplete`).

**Disk log** (`internal/disklog`; [On-disk format](design.md#on-disk-format))

- [x] **Segments and superblock** (component). Segment size min(64 MiB, disk ÷ 4096) rounded down to a power of two; superblock and segment header each one block, the header carrying format version, stream and lane. Golden bytes are checked in as `internal/disklog/testdata/log_format_golden.txt`. Tests: geometry for every disk size and the too-small and too-large disks (`TestGeometryFor`, `TestGeometryAddressing`); both blocks round-trip, every single bit flip of a header fails to decode, and each kind of damage gets its error (`TestSuperblockRoundTrip`, `TestSuperblockErrors`, `TestSegmentHeaderRoundTrip`, `TestSegmentHeaderBitFlips`, `TestSegmentHeaderErrors`); the golden bytes (`TestGoldenBytes`); anything the decoders accept re-encodes to itself (`FuzzDecodeSuperblock`, `FuzzDecodeSegmentHeader`).
- [x] **Record codec** (component). Header blocks holding the log's entries, a CRC32C per data block and a header checksum, capped at `max_group_commit_bytes`; a record read back under another log ID, segment sequence or offset is a mismatch, so a recycled segment's old records are never accepted. Review with a property test: for every torn prefix and every subset of landed sectors, decoding returns the whole record or rejects it. Tests: layout sizes and payload offsets (`TestLayoutExamples`, `TestPayloadOffset`); random records round-trip (`TestRecordRoundTrip`, `TestRecordRoundTripSeed1`); every subset of landed blocks or 512-byte sectors decodes whole or not at all (`TestTornBlocksSeed4`, `TestTornSectorsSeed5`); any corrupted byte is rejected (`TestRecordCorruptByte`); each kind of damage gets its error (`TestRecordErrors`); `FuzzDecodeRecord`, `FuzzBlockCRC`; `BenchmarkAppendRecord16`, `BenchmarkDecodeRecord16`.
- [x] **Group commit** (component). One write and one flush per round, accepting records from many producers, three streams in lanes, writing producers' buffers as one vectored write. A round's write and flush are emitted together so the driver can link them, and up to `commit_depth` rounds are in flight, a flush submitted only once its own and every earlier round's write have completed ([One flush per round](design.md#on-disk-format)). A refused item's buffer stays with the caller. Review when the action trace shows exactly one `DiskFsync` per round, no block is copied, and a manifest larger than a record goes out in pieces. Tests: `TestOneWriteAndOneFlushPerRound`, `TestNoBlockIsCopied`, `TestManifestLargerThanARecordGoesInPieces`; lanes take turns and each opens its own segment (`TestLanesTakeTurns`); `NoSpace` fails a stream's whole queue, so nothing is written out of order (`TestNoSpaceFailsTheStreamsWholeQueue`); a full pool never stalls a round (`TestAFullPoolNeverStallsARound`); disk and flush errors fail the log and leave rounds in flight in doubt (`TestDiskErrorFailsTheLog`, `TestDiskErrorWithRoundsInFlight`, `TestAnErrorOnALaterFlushFailsTheLog`); at depth 2 a flush waits for every earlier write and a round appends only once its segment's opening round is durable (`TestCommitDepthWaitsForEarlierWritesBeforeAFlush`, `TestARoundAppendsOnlyOnceItsSegmentsOpeningRoundIsDurable`); a checkpoint's manifest has the right base, runs and usage (`TestCheckpointEndToEnd`); `BenchmarkGroupCommitRound`.
- [x] **Write-side decode check** (test). With the check on, as in the package's tests and the simulator, group commit decodes every record it just encoded and asserts it holds exactly what was submitted, and a round never builds a record with no entries. Review when a deliberately broken encoder fails the simulator's seeds. Tests: a broken encoder panics in the check (`TestDecodeCheckCatchesABrokenEncoder`); every accepted item ends durable in a record that decodes to it (`TestEveryAcceptedItemDecodes`); anything `Submit` accepts decodes, and everything else is refused with an error (`TestAnythingSubmitAcceptsDecodes`).
- [x] **Segment usage table** (component). Each manifest carries state, live blocks and newest LSN per segment, with quarantined as one of the states so a quarantine outlives the start that found it. A segment is free only because the table says so, and a rebuild reports a gap the table cannot explain as corruption ([Free space](design.md#on-disk-format)). Tests: a damaged header never frees a used segment (`TestUsageTableNeverFreesAUsedSegment`); a zeroed header over records past the replay point, or over a segment opened after the manifest, is corruption (`TestUsageTableZeroedHeaderOverRecordsPastTheReplayPointIsCorruption`, `TestUsageTableZeroedHeaderOfASegmentOpenedAfterTheManifestIsCorruption`); a quarantine is kept across starts (`TestUsageTableKeepsAQuarantine`); a row past the disk is corruption (`TestUsageTableNamingASegmentPastTheDiskIsCorruption`); `NextSeq` tells a freed segment from a reused one in every crash order (`TestNextSeqTakenAtBeginLosesTheRoundInFlight`, `TestRecoverFreedSegmentKeepingItsHeaderIsFree`, `TestRecoverReusedSegmentRowComesFromReplay`).
- [x] **Recovery** (component). Load the newest named manifest and the runs it names, replay the log after each index's replay LSN, lane by lane; the tail rule drops only rounds that may have been in flight and reports anything else as corruption, writing nothing ([Recovery](design.md#on-disk-format)). Segment headers are read with many reads in flight. Tests: crashes at random keep every acknowledged record, open and rebuild agree, and a second recovery changes nothing (`TestRandomCrashesKeepAcknowledgedRecords`, `FuzzRecover`); a crash at every action recovers (`TestCrashAtEveryAction`, `TestCrashAtEveryActionInTheReserve`), and planted recovery bugs fail it (`TestCrashAtEveryActionCatchesPlantedRecoveryBugs`, `TestCrashOracleCatchesPlantedBugs`); a torn tail is overwritten safely (`TestRecoverOverwritesATornTail`); the log ends only where no later header names it durable (`TestRecoverEndsTheLogOnlyWhereNoLaterHeaderNamesItDurable`); a duplicate LSN is corruption (`TestRecoverReportsADuplicateLSN`); a durable manifest is never dropped (`TestRecoverRefusesToDropADurableManifest`); a corrupt recovery writes nothing (`TestRecoveryThatEndsCorruptWritesNothing`); recovery flushes before it reports (`TestRecoverFlushesBeforeReportingRecovered`); each lane is read from its own start (`TestRecoverReadsEachLaneFromItsOwnStart`); one checkpoint over several indexes recovers all to one LSN (`TestOneCheckpointOverTwoIndexesAndAShardReplica`).
- [x] **Superblock copy** (component). A second superblock in the last block of segment 0, written and flushed after the first; recovery uses a valid copy and rewrites a damaged one, but never writes a block 0 of zeros or another format ([superblock repair](design.md#superblock-repair)). Tests: `TestSuperblockCopyRepairsADamagedCopy`, `TestSuperblockCopyRestoresAnUnreadableBlock0`, `TestSuperblockCopyNeverOverwritesAReusedBlock0`; no valid superblock on a written disk is `Unrecognized` (`TestNoValidSuperblockOnAWrittenDiskIsUnrecognized`); a copy where its own geometry does not put it, or a geometry larger than the disk, is not used (`TestSuperblockCopyWithAnImpossibleGeometryIsNotUsed`, `TestSuperblockCopyRestoresABlock0ClaimingMoreBlocksThanTheDisk`); a crashed reformat recovers as the new log (`TestSuperblockCopyAfterAReformatThatCrashed`).
- [x] **Quarantined segments** (component). A segment whose header fails to decode is free only if none of its blocks holds a record header of this log; one past the replay point makes the log corrupt at that record, and otherwise recovery reports the segment quarantined and group commit never reuses it. Review with the simulator's bit flips on segment headers: no acknowledged record is ever overwritten. Tests: `TestQuarantinedSegmentsAreNeverReused`, `TestQuarantineReplayThroughADamagedSegmentIsCorruption`.

**LSM tree and chunk index**

- [x] **LSM tree** (component, `internal/lsm`). A copy-on-write B+-tree memtable of 4 KiB pages in pointer-free slabs ([Runtime in Go](design.md#runtime-in-go), [tech debt](tech-debts.md#workaround-lsm-runs-and-retained-raft-entries-on-the-go-heap)); a flush that streams the frozen memtable into the log as a sorted run, one piece at a time; runs held in memory behind fence pointers; point-in-time views; a restore that loads runs and replays ([The LSM tree](design.md#on-disk-format)). Review against the [Go memtable spike](design.md#appendix-go-memtable-spike) and [MetaStore memory spike](design.md#appendix-metastore-memory-spike): collection under 1 ms at 20 million entries, a flush's peak the tree plus one piece, a run near the spike's bytes per file, and a get that touches the memtable and each run once. An entry larger than a piece is an error, not a panic. Tests: the memtable reads as a map (`TestMemtableMatchesModel`); views copy on write (`TestViewsCopyOnWrite`, `TestViewDuringFlush`); a leaf redistributes before it splits (`TestLeafRedistribution`); a flush works at any piece size and keeps its frozen view (`TestFlushAtAnyPieceSize`, `TestFlushKeepsFrozenView`, `TestFlushPeakMemory`); restore is runs plus replay (`TestRestoreIsRunsPlusReplay`); a malformed run is refused (`TestLoadRunRejects`, `FuzzLoadRun`); `TestEntryLargerThanPiece`, `TestGetTouchesEachLayerOnce`, `TestRunBytesPerFile`, `TestFlushFailedKeepsFrozen`; `BenchmarkCollection`, `BenchmarkGet`, `BenchmarkFloor`, `BenchmarkPut`, `BenchmarkIterNext`.
- [x] **Compaction** (component, `internal/lsm`). RocksDB's universal rules over runs adjacent in age: size amplification, size ratio, then the auto-tuned run limit ([LSM tree](design.md#on-disk-format)). Merges run on a worker goroutine, the owner installs the result, and the old runs are dead once a manifest that no longer names them is durable and a segment header names it; the picker skips runs a running merge holds, one scheduler per disk runs its indexes' merges by score, and a merge installs in steps. Review when a view opened before a compaction still reads the old runs, a crash between the new run and its manifest recovers to the previous manifest plus replay, and the [LSM compaction study](design.md#appendix-lsm-compaction-study)'s alternating, bursty and log-uniform flush sequences stay within the run limit. Tests: RocksDB's picker cases and ours (`TestPickerCases`); the auto limit (`TestAutoRunLimit`); flush sequences within the limit, through the model and the real tree (`TestFlushSequencesModel`, `TestFlushSequencesRealTree`); `TestCrashDuringMergePicksItAgain`, `TestTwoMergesInstallInEitherOrder`, `TestSchedulerOrder`, `TestSchedulerWorkers`; merges in steps read and restart correctly (`TestMergeInSteps`, `TestRestartBetweenSteps`, `TestCrashBeforeStepManifest`).
- [x] **Chunk index** (component, `internal/chunkstore`). In the LSM tree: one entry per chunk, a live map trimmed and split on insert so it never overlaps, a frozen copy of the map per `freeze` entry, and live blocks counted per record for the cleaner ([chunk index](design.md#on-disk-format)). Rebuild by scanning record headers, punches and freezes included. Review when replaying records in LSN order rebuilds identical live and frozen maps, a read of the live version costs one lookup per block, and a read at a snapshot epoch finds the right frozen version. Tests: key byte order equals logical order (`TestKeyOrder`); writes, trims, freezes and punches map as specified (`TestIndexScenarios`, `TestFreezes`); a move changes every map still pointing at its source (`TestMoves`); the index matches a model of whole-map copies (`TestIndexMatchesModel`); replay past pending writes reads as a rebuild does (`TestReplayPastPendingWrites`); open and rebuild equal the live index (`TestRecoveryAndRebuildEqualLiveIndex`); a planted overlap is found (`TestCheckFindsOverlap`); `BenchmarkLookup`, `BenchmarkApplyWrite`, `BenchmarkApplyMove`.
- [x] **Range removals** (component, `internal/lsm`, `internal/chunkstore`). `Tree.DeleteRange(lo, hi)`: memtable fragments in a second page tree, run fragments in blocks of their own, reads that stop at or skip past a covering fragment in one search, filters and run bounds that never hide one, and flushes and merges that keep a fragment only while an older run holds a key in it. A whole-chunk punch, a released frozen version and a write covering two or more whole extents are one range removal each ([LSM tree](design.md#on-disk-format)). Review when a chunk rewritten whole over 1,024 one-block extents takes at most two searches per lookup in the memtable, after its flush and after a merge, a range removal and a cut each allocate nothing and cost one search, and the property test passes with filters on ([LSM deletions study](design.md#appendix-lsm-deletions-study)). Tests: fragments merge and cut as specified (`TestMemtableFragments`); an empty range is refused (`TestEmptyRangeRefused`); random range removals read as a map, and planted bugs fail it (`TestRangeRemovalsMatchModel`, `TestRangeModelCatchesPlantedBugs`); `TestSizeBounds`, `TestCutTooLongForAFragment`, `TestScanBoundedInsideFragment`, `TestMergeFragments`, `TestFlushRemovalsForwardCursors`, `TestRangeRemovalAndCutOneSearch`, `TestRunFragmentFormat`; in the chunk index, `TestRangeRemovalUses`, `TestRewriteOver1024Extents`, `TestRangeRemovalsMatchPointRemovals`; `BenchmarkDeleteRange`, `BenchmarkCut`, `BenchmarkLookupRewritten`.
- [x] **Run checks** (component, `internal/lsm`). Always on: entry and fragment counts on flush and merge, and a CRC32C per in-memory piece verified before a merge reads it and as a flush writes it; a failure fails the flush or merge, and the index is rebuilt from the log ([The LSM tree](design.md#on-disk-format)). Behind `Config.Check`: a flush decodes every piece it built, a merge checks its output's key order, and the run list stays ordered with no repeats; a failure panics ([Testing strategy](design.md#testing-strategy)). Review when a flipped bit in an in-memory piece fails the next merge, and a planted encoder or merge bug fails the package's tests in the flush or merge that made it. Tests: `TestFlushCountCheck`, `TestMergeCountCheck`, `TestMergeVerifiesPieceChecksums`, `TestFlushVerifiesRewrittenRuns`, `TestFlushDecodeCheck`, `TestMergeOrderCheck`, `TestRunOrderCheck`, `TestCheckFailsInALaterStep`; in the store, a failed check rebuilds the index and a second failure stops it (`TestRunCheckRebuilds`, `TestMergeCheckRebuilds`, `TestARunCheckFailingAfterARebuildStopsTheStore`), and a damaged piece fails the rebuild (`TestRebuildFromADamagedRunIsCorrupt`); `BenchmarkMergeChecksums`.
- [x] **Metamorphic index tests** (test, `internal/sim/metamorphic`, `internal/lsm`, `internal/chunkstore`). A runner shared by both indexes: ops in a text form, option sets at their extremes (memtable only, small to large pieces, frequent flushes, eager, held, late and concurrent merges, a fixed run limit, failed flushes and restarts, point removals in place of range removals, the linear merge), history diff against a model, and reduction of a failure to a data-driven regression case written before its fix ([Testing strategy](design.md#testing-strategy)). Review when the [metamorphic testing spike](design.md#appendix-metamorphic-testing-spike)'s five planted bugs each fail under an option set. Tests: both indexes match their models under every set (`TestMetamorphic` in `internal/lsm` and `internal/chunkstore`); each set reaches its extreme (`TestMetamorphicSetsReachTheirExtremes`); planted bugs fail and regressions catch their plants (`TestMetamorphicFindsPlantedBugs`, `TestMetamorphicRegressions`, `TestMetamorphicRegressionsCatchTheirPlants`); a failure reduces (`TestMetamorphicReducesAFailure`, `TestReduce`); malformed ops lines are refused (`TestMetamorphicParseRejects`, `TestParse`); a cadence counts writes absorbed between a flush's pieces (`TestRunFlushEveryCountsAbsorbedWrites`).
- [x] **Run filters** (component, `internal/lsm`, `internal/chunkstore`). A cache-local Bloom filter per run, 10 bits per key, in RocksDB's full-filter format as Pebble writes it, ported with its BSD notice, tests and golden bytes; partitioned per merge step, written after the run's blocks, loaded on restore, which refuses a filter holding other keys than its tree's. An extractor per index: whole keys, a closed prefix, or both; the chunk index's lookups use the chunk prefix ([LSM tree](design.md#on-disk-format)). Review when a miss over 24 runs searches at most 0.5 runs on average and allocates nothing, a bounded floor equals a floor plus the prefix check under the property tests, and a restored tree's filters read as before. Tests: Pebble's ported tests (`TestSmallBloomFilter`, `TestBloomFilter`, `TestBloomHash`); false positives within bounds (`TestFilterSizeAndFalsePositives`); prefixes held once (`TestFilterPrefixKeys`); probes newest first (`TestFilterProbeOrder`); a filter never holds fragments (`TestFilterHoldsNoFragments`); `TestFilterMissesOver24Runs`, `TestLookupOver24Runs`; partitions (`TestFilterPartitionFormat`, `TestStepPartitionsReadLikeTheMap`, `TestPartitionedLookupsProbeOnce`, `FuzzFilterParts`); `BenchmarkFilterProbe`, `BenchmarkPartitionedLookups`.
- [x] **Filter option sets** (test, `internal/lsm`, `internal/chunkstore`). Both indexes' metamorphic tests also run with filters off and with every probe answering "maybe" (`lsm.Config.Probe`), the chunk index's runs holding its chunk-prefix filters under every set ([Testing strategy](design.md#testing-strategy)). Review when both pass under them and each searches more layers than with filters on, filters off probing none. Tests: `TestMetamorphic`, `TestMetamorphicSetsReachTheirExtremes`, `TestMetamorphicOpsCoverTheIndex`.
- [x] **Chunk reader** (component, `internal/lsm`, `internal/chunkstore`). One reader per chunk per read: it probes the run filters once with the chunk's prefix and serves ascending blocks by stepping forward, as Pebble's `TrySeekUsingNext` does, searching a layer again only past 16 entries ([chunk index](design.md#on-disk-format)). Review when a read of blocks 3, 4 and 700 of one chunk probes the filters once and serves 4 without a search, and the lookup benchmarks stay at zero allocations. Tests: `TestReaderSteps`, `TestFloorPrefixSteps`; a reader used after the index changes panics under `Check` (`TestReaderAfterChangePanics`); `BenchmarkRead8Blocks`.
- [x] **Heap merge** (component, `internal/lsm`). The iterator merges the memtables and runs with a min-heap, as Pebble's `mergingIter` does. Review when a scan step over 24 runs costs less than twice the step over 6, with zero allocations. Tests: ties return the newest layer's entry once (`TestHeapMergeTies`, `TestScanTies`); a scan across k fragments searches at most k + 1 times (`TestScanFragmentSearches`); seeks allocate nothing (`TestSeekAllocatesNothing`); one or no source works (`TestScanFewSources`, `TestScanEdges`); `BenchmarkIterNextRuns`.
- [x] **Absent freeze** (component, `internal/chunkstore`). A freeze of version 0 of a chunk with no entry records it absent at the cut: an empty frozen map that `LookupAt` reads as a miss, listed first among the chunk's frozen versions, skipped by cleaner moves, and holding no keys to release; a chunk with a tombstone freezes the tombstone's version instead ([Versions share blocks](design.md#on-disk-format)). Tests: the [chunk epochs spike](design.md#appendix-chunk-epochs-spike)'s cases read a chunk first written after a cut as absent at that snapshot (`TestAbsentFreezeE1`, `TestAbsentFreezeE2`, `TestAbsentFreezeE3`); freezes replayed change nothing (`TestAbsentFreezeScenarios`); a punch after the absent freeze reads absent at the snapshot and zeros live (`TestAbsentFreezeOfPunch`); a tombstone's snapshot reads zeros (`TestFreezeOfTombstone`); releasing the absent version removes no keys (`TestReleaseAbsentVersion`).
**ChunkStore and cleaner** (`internal/chunkstore`, `internal/disklog`)

- [x] **Single-node ChunkStore** (component, `chunkstore.Store`). `Write`, `Punch`, `Read`, `Flush` and `Seal` on one disk as a sans-IO machine taking requests and disk completions: versions of a 32-bit interval over a 32-bit counter, `expectVer` against the newest ordered version, `atVer` reads, tombstones, byte ranges merged into whole blocks against the newest ordered version, writes larger than a record as several items of one version, and the log's failure events ([Operations on one disk](design.md#data-layer-chunkstore), [Byte ranges become whole blocks](design.md#data-layer-chunkstore)). ## Phase 6: file frontend

Phase 6 is built beside the unticked items of phases 4 and 5, not after them: an item names the ones it needs, and the rest wait for nothing. Its first milestone, **FUSE mount on one node**, is one node with a FUSE mount that can create, write, read, close-to-open and unlink. That mount writes through under a grant of 0, so it needs none of phase 4's unticked space items, and leaves unlinked files' chunks on the purge list until the Purger consumes it. Every protocol phase 6 runs has its model already: the [sessions](../models/sessions/sessions.tla), [purge](../models/purge/purge.tla) and [cache-mode recall](../models/recall/recall.tla) models, the last for the open registry and the owner's grace period, whose cache modes wait for phase 7. The daemon's side of space grants is accounting, which the simulator's grant invariant checks. Each negative that phase 6 plants is named in its item, and its row in `scripts/model-rules.tsv` names that item. Phase 6 is done once every item here is ticked and, from phase 4, **Grants against a stuck refill** and **No grant raised before recovery** are too: both bound how much a refill can take of the room the grants promise, which matters only once daemons buffer.
