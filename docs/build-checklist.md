# Build checklist: phases 1 to 5

Phases 1 to 5 of the [roadmap](design.md#roadmap-and-open-questions) produce nothing a user can run; the first usable product is phase 6. This list breaks those phases into building blocks that can each be reviewed on their own. An item is a **component** (a state machine or driver), a **lib** (a dependency or a shared encoding) or a **test** (a suite, harness or measurement). Each one names its package under `internal/` and what must hold before it is reviewed. The design lives in [design.md](design.md); items link to it rather than restate it. Each item has a section in [test-scenarios.md](test-scenarios.md), and its tests cover every scenario in it; an "Open:" line there is settled in the design before the item is reviewed.

Items are in build order within a phase. An item can start once the items it uses are reviewed.

**Every item, before review**

- `scripts/lint.sh` passes, and sans-IO packages pass the sans-IO analyzer ([Modularity](design.md#modularity-sans-io-core-pluggable-drivers)).
- Hot-path benchmarks report zero allocations per operation.
- Unit tests feed events and assert on actions, with no mocks; every decoder has a fuzz test.
- New invariants are registered with the simulator's checker in the same change.
- Every failing seed found so far is a regression test.
- `docs/design.md` matches the code, and `docs/tech-debts.md` lists any pin or workaround.

## Phase 1: sans-IO core and simulator

**Tooling**

- [x] **Module, toolchain and lint** (lib). One Go module pinned with `toolchain go1.27.0`; `scripts/lint.sh` runs `gofmt`, `go vet`, `staticcheck`, `govulncheck` and a dependency license check.
- [x] **Sans-IO analyzer** (lib, `tools/sansio`). A `go/analysis` pass that `scripts/lint.sh` runs through `go vet -vettool` on every sans-IO package ([rules for state machines](design.md#modularity-sans-io-core-pluggable-drivers)). Review when it rejects a planted `range` over a map, `time.Now`, `go` statement, channel, `sync` import and global `math/rand` call in `internal/core`, and accepts the same code in a test file and in `internal/loop`.

**Foundations** (`internal/core`)

- [x] **Event and Action types** (component). `Tick`, `IOID`, `TimerID`, `NodeID`, `Context`, `Event`, `Action` as in [Modularity](design.md#modularity-sans-io-core-pluggable-drivers). `DiskWrite` takes a vector of buffers, so group commit writes producers' buffers in place without copying them into one image. Review when the three driver-contract rules are expressible: data travels only as `IOBuf` handles, control messages of 256 bytes or less go inline, and a `PeerLost` fails a peer's outstanding requests.
- [x] **Buffer pool interface** (component; heap pool in `internal/sim`). `IOBuf` handles of a slot and a generation, from a pool of explicit size. Review when an exhausted pool is an error the caller handles, never a panic or a heap fallback, and a stale handle is caught.
- [x] **Seeded RNG** (lib). `math/rand/v2` with a seeded PCG or ChaCha8 source per state machine, and a golden stream checked in.
- [x] **IDs and hashing** (lib). 128-bit `ChunkID` packing and the PG hash (`xxh3_64`, seed 0, top bits) from the [key layout](design.md#metadata-layer-metastore) and [placement groups](design.md#data-layer-chunkstore). Both are frozen disk format: the test reads `internal/core/testdata/chunk_id_golden.txt` unchanged.
- [x] **CRC32C** (lib). `hash/crc32` with the Castagnoli table; review with the RFC 3720 test vectors.
- [x] **Lease clocks in the context** (component). `Context.Raw`, the time on `CLOCK_MONOTONIC_RAW` in ticks beside `Now` on `CLOCK_BOOTTIME`, and a `Resumed` event kind, as in [Modularity](design.md#modularity-sans-io-core-pluggable-drivers): every lease is counted on both clocks and a holder ends its leases on `Resumed` ([Epoch changes](design.md#epoch-changes-and-failure-detection)). Review when a test can set `Now` and `Raw` apart and the simulated disk's harness and every existing machine's tests set both.
- [x] **Peer requests** (component). Outstanding requests per peer with their deadlines and buffers: a timeout keeps the buffer, `PeerLost` fails them all and returns their buffers, and a stale `Timer` is ignored.

**Disk log** (`internal/disklog`; [On-disk format](design.md#on-disk-format))

- [x] **Segments and superblock** (component). Segment size min(64 MiB, disk ÷ 4096) rounded down to a power of two; the segment header carries the format version and the stream tag. Golden bytes are checked in as `internal/disklog/testdata/log_format_golden.txt`.
- [x] **Record codec** (component). Header blocks holding write, punch, freeze and blob entries, a CRC32C per data block and a header checksum, capped at `max_group_commit_bytes`. Review with a property test: for every torn prefix and every subset of landed sectors, decoding returns the whole record or rejects it.
- [x] **Group commit** (component). One write and one flush per round, accepting records from many producers (chunk writes and any number of shards), three streams in lanes, writing producers' buffers as one vectored write. A round's write and flush are emitted together so the driver can link them, and up to `commit_depth` rounds are in flight, a flush submitted only once its own and every earlier round's write have completed ([One flush per round](design.md#on-disk-format)). Review when the action trace shows exactly one `DiskFsync` per round, no block is copied, and a manifest larger than a record goes out in pieces.
- [x] **Write-side decode check** (test). With the check on, as in the package's tests and the simulator, group commit decodes every record it just encoded and asserts it holds exactly what was submitted, and a round never builds a record with no entries. A property test checks that anything `submit` accepts decodes. Review when a deliberately broken encoder fails the simulator's seeds.
- [x] **Segment usage table** (component). Each manifest carries state, live blocks and newest LSN per segment, with quarantined as one of the states so a quarantine outlives the start that found it. A segment is free only because the table says so, never because its header reads as zeros or a damaged header covers no record of this log, and a rebuild reports a gap the table cannot explain as corruption ([Free space](design.md#on-disk-format)). Recovery takes free segments from the newest manifest's table and reads in full only damaged segments the table cannot vouch for, so a segment the table quarantines is not read again. A used segment left empty by rounds recovery dropped counts zero live blocks.
- [x] **Recovery** (component). Load the last manifest and the runs it names, replay the log after each index's replay LSN; a checkpoint is due once `max_replay_bytes` of records follow the manifest. The tail rule accepts up to `commit_depth` torn or missing records and drops everything after the first. Segment headers are read with many reads in flight, since a disk has 4,096 to 262,144 of them.
- [x] **Superblock copy** (component). A second superblock in the last block of segment 0, written and flushed after the first; recovery uses a valid copy and rewrites a damaged one, but never writes a block 0 of zeros or another format ([superblock repair](design.md#superblock-repair)).
- [x] **Quarantined segments** (component). A segment whose header fails to decode is free only if none of its blocks holds a record header of this log; one past the replay point makes the log corrupt at that record, and otherwise recovery reports the segment as quarantined and group commit never reuses it. Review with the simulator's bit flips on segment headers: no acknowledged record is ever overwritten.

**LSM tree and chunk index**

- [x] **LSM tree** (component, `internal/lsm`). A copy-on-write B+-tree memtable of 4 KiB pages in pointer-free slabs, on the Go heap until the event loop's off-heap slabs exist ([Runtime in Go](design.md#runtime-in-go), [tech debt](tech-debts.md#workaround-lsm-pages-and-runs-on-the-go-heap)); a flush that freezes it, starts an empty one and streams the frozen one into the log as a prefix-compressed sorted run, one piece at a time, each built at its final size; runs held in memory behind fence pointers; point-in-time views; a restore that loads runs and replays ([The LSM tree](design.md#on-disk-format)). A leaf redistributes into a neighbour before it splits. Review against the [Go memtable spike](design.md#appendix-go-memtable-spike) and [MetaStore memory spike](design.md#appendix-metastore-memory-spike): collection under 1 ms at 20 million entries, a flush's peak the tree plus one piece, a run near 135 B per file, and a get that touches the memtable and each run once. An entry larger than a piece is an error, not a panic.
- [x] **Compaction** (component, `internal/lsm`). RocksDB's universal rules over runs adjacent in age: size amplification, size ratio, then the auto-tuned run limit ([LSM tree](design.md#on-disk-format)). Merges run on a worker goroutine, the owner swaps the result in, and the old runs are dead to the cleaner once a manifest that no longer names them is durable and a segment header names it; the picker skips runs a running merge holds, and one scheduler per disk runs its indexes' merges by score. Review when a view opened before a compaction still reads the old runs, a crash between the new run and its manifest recovers to the previous manifest plus replay, and the [LSM compaction study](design.md#appendix-lsm-compaction-study)'s alternating, bursty and log-uniform flush sequences stay within the run limit.
- [x] **Chunk index** (component, `internal/chunkstore`). In the LSM tree: one entry per chunk (version, snapshot epoch of its last freeze); a live map `(pool, h, chunk_id, 0, first block) → (version, location, block count, record header)` trimmed and split on insert so it never overlaps; a frozen copy of the map per `freeze` entry; live blocks counted per record for the cleaner ([chunk index](design.md#on-disk-format)). Rebuild by scanning record headers, punches and freezes included. Review when replaying records in LSN order rebuilds identical live and frozen maps, a read of the live version costs one lookup per block, and a read at a snapshot epoch finds the right frozen version.
- [x] **Range removals** (component, `internal/lsm`, `internal/chunkstore`). `Tree.DeleteRange(lo, hi)`: a memtable's fragments in a second copy-on-write page tree, turning its entries in the range into removals and cutting a later write's key out of a fragment; a run's fragments in blocks of their own after its entries, marked in the piece trailer (golden bytes updated); a floor that keeps each layer's candidate and moves older layers below a covering fragment in one search, a get that stops at a covering fragment, a scan that skips past one keeping a positioned fragment per layer; run filters and run bounds that never hide a fragment; a flush and a merge that keep a fragment only while an older run holds a key in it, checking fragments against older runs with the forward cursors point removals already use. A whole-chunk punch and a released frozen version are one range removal each. The chunk index removes the keys of the extents a write covers with one range removal when there are two or more. `MaxKey` rises from 1,024 to 1,032 bytes with `MaxValue` at 1,000, the block decoder's check following the constant, and tests assert both the point-entry bound (key plus value at most 2,033 bytes) and a fragment's two bounds of 1,000 bytes fitting half a page ([LSM tree](design.md#on-disk-format)). Review when a chunk rewritten whole over 1,024 one-block extents takes at most two searches per lookup in the memtable, after its flush and after a merge, the zero-allocation lookup benchmarks still hold, a range removal and a cut each allocate nothing and cost one search (plus their insert descents) with 262,144 fragments in a memtable, and the property test passes with filters on ([LSM deletions study](design.md#appendix-lsm-deletions-study)). Prototype: `spikes/lsm-runs/lsmx` and `cix`.
- [x] **Run checks** (component, `internal/lsm`). Always on: entry and fragment counts on flush and merge, and a CRC32C per in-memory piece verified before a merge reads it; a failure fails the flush or merge, and the index is rebuilt from the log ([The LSM tree](design.md#on-disk-format)). Behind `Config.Check`, as group commit's: a flush decodes every piece it built, a merge checks its output's key order against its inputs, and the run list stays ordered by sequence number with no repeats; a failure panics ([Testing strategy](design.md#testing-strategy)). Review when a flipped bit in an in-memory piece fails the next merge, and a planted encoder or merge bug fails the package's tests in the flush or merge that made it.
- [x] **Metamorphic index tests** (test, `internal/sim/metamorphic`, `internal/lsm`, `internal/chunkstore`). A runner shared by both indexes: ops in a text form, an option set's cadence of flushes, failed checkpoints, held merges, writes and reads between a flush's pieces and restarts, a log that keeps live pieces and the newest manifest's replay point, history diff and reduction. Each index has a seeded generator (for the tree writes, removals, range removals, gets, floors, scans, views; for the chunk index writes, punches, freezes after cuts, cleaner moves and releases in version order, read block by block live and at snapshot epochs), a model, and option sets at their extremes whose histories must equal the model's ([Testing strategy](design.md#testing-strategy)): memtable only, 256-byte to 1 MiB pieces, flushes after every few writes, eager, held and late merges, two merges at once, a fixed run limit, failed flushes and restarts after each, range removals replaced by point removals, and, for the tree, the linear merge in scans, flushes and merges. The [metamorphic testing spike](design.md#appendix-metamorphic-testing-spike)'s five planted bugs each fail under an option set, and a failure reduces to a data-driven regression case. Prototype: `spikes/lsm-study-testing`.
- [x] **Run filters** (component, `internal/lsm`, `internal/chunkstore`). A cache-local Bloom filter per run, 10 bits per key, in RocksDB's full-filter format as Pebble's `sstable/tablefilters/bloom` writes it, ported with its BSD notice, its tests and its golden bytes; filled while the run streams out and sized from what the flush or merge knows: the frozen memtable's entry count, or the sum of the inputs' filter key counts; written after the entries and range removals in pieces of its own, headed by what it holds and its key count, marked in the trailer (golden bytes updated), and loaded on restore, which refuses a filter holding other keys than the tree's. Each run keeps its last key. An extractor per index in `Config`: whole keys, a prefix, or both. `Get` probes the filters newest first; `FloorPrefix` and `SeekPrefixGE` probe once with the prefix. The chunk index's lookups use the chunk prefix ([LSM tree](design.md#on-disk-format)). Review when a miss over 24 runs searches at most 0.5 runs on average and allocates nothing, a bounded floor equals a floor plus the prefix check under the property tests, and a restored tree's filters read as before. Prototype: `spikes/lsm-study-reads`.
- [ ] **Filter option sets** (test, `internal/lsm`, `internal/chunkstore`). Both indexes' metamorphic tests gain two option sets: filters off, and every probe answering "maybe" ([Testing strategy](design.md#testing-strategy)). Review when both indexes' metamorphic tests pass under them.
- [ ] **Chunk reader** (component, `internal/lsm`, `internal/chunkstore`). One reader per chunk per read: it probes the run filters once with the chunk's prefix and serves ascending blocks by stepping forward from the last one, as Pebble's `TrySeekUsingNext` and RocksDB's reseek within the current block do ([chunk index](design.md#on-disk-format)). Review when a read of blocks 3, 4 and 700 of one chunk probes the filters once and serves 4 without a search, and the lookup benchmarks stay at zero allocations.
- [x] **Heap merge** (component, `internal/lsm`). The iterator merges the memtables and runs with a min-heap, as Pebble's `mergingIter` does. Review when a scan step over 24 runs costs less than twice the step over 6, with zero allocations (54 against 37 ns on the Apple M4 Pro, 65 against 44 on an Intel Core Ultra 5 235U, where the linear merge took 165 against 56), and `BenchmarkIterNext` is back under its 42.5 ns from before Run checks on the M4 Pro (35.6 ns).
- [x] **Absent freeze** (component, `internal/chunkstore`). A freeze of version 0 of a chunk with no entry records it absent at the cut: an empty frozen map that `LookupAt` reads as a miss, listed among the chunk's frozen versions and skipped by cleaner moves ([Versions share blocks](design.md#on-disk-format)). The index at 676095b reads a chunk first written after a cut at that snapshot; the [chunk epochs spike](design.md#appendix-chunk-epochs-spike)'s E1 to E3 become regression tests first, and its `absent/index.diff` is a prototype of the fix.

**ChunkStore and cleaner** (`internal/chunkstore`, `internal/disklog`)

- [ ] **Single-node ChunkStore** (component). `Write`, `Punch`, `Read`, `Flush` with versions, `expectVer` compare-and-set, `atVer` reads and tombstones ([Data layer](design.md#data-layer-chunkstore)). Byte ranges become whole blocks: a block a write or punch covers in part is merged against the newest version ordered for it, a pending write's merged block or the live map (zeros if unwritten or punched), with the base's CRC32C checked, the chunk's later operations waiting behind a base read, and only whole blocks logged; whole blocks inside a punch get a punch entry. Review with a byte-range oracle over unaligned writes of 1 byte to 3 blocks, pipelined to one block, as the [sub-block writes spike](design.md#appendix-sub-block-writes-spike)'s M1 and M2. A chunk's writes are mapped in version order, and the first write after a cut to a chunk with no version puts a freeze of version 0 in its record. Versions are a 32-bit PG interval number over a 32-bit counter per chunk, fixed here: a write takes the chunk's newest ordered version plus one within the interval, or `(interval, 1)`; interval numbers and counters start at 1, and on one node the interval is a local number raised when a chunk's counter runs out; a write is mapped when it commits, which on one node is when its record is durable. A write larger than one record (`max_group_commit_bytes`, 1 MiB, so every whole 4 MiB chunk until Chunk slots lands) goes to the log as several items of the same version, acknowledged once all are durable. It handles `Failed` and `CheckpointFailed` events from the log, and keeps the index's frozen memtable when a checkpoint fails. When a flush or merge of the index fails a [run check](design.md#on-disk-format) (`lsm.ErrCheck`), it rebuilds the index from the log while the disk's other indexes serve. It hands the log one run piece at a time, each once the one before is durable. `Seal` exists in the API only.
- [x] **Segment reserve** (component, `internal/disklog`). A reserve of ⌈(2 × `max_replay_bytes` + merge workers × `compaction_step_bytes`) ÷ segment⌉ + victims per pass segments, at least 8 (`ReserveSegments`), that only checkpoints, the cleaner and merge steps may use; a reserve of every usable segment is refused at format and open ([Free space](design.md#on-disk-format)). While only the reserve is free, group commit holds ordinary items in submit order with their buffers (`Stalled`), never opens a reserve segment for them, and fails them with `NoSpace` when the owner reports that the cleaner has no victim (`FailStalled`); a checkpoint that finds no segment free waits the same way and the same report fails it. Review when a disk filled to its reserve still finishes a checkpoint and a held write goes out once segments are freed, each rule failing under a planted bug. A merge step and a cleaner pass finishing on a full disk are reviewed with their items, and the bytes held beyond the manifests with the invariant checker.
- [ ] **Merge steps** (component, `internal/lsm`, `internal/disklog`). A merge installs its output every `compaction_step_bytes`: the owner appends the step's pieces to the output run and sets each input's bound to the step's last key; a run holds only keys above its bound, its fragments clipped; the manifest edit carries the bounds, and input pieces wholly below a bound count dead in the usage table once it is durable; a restart resumes the merge from the bound; output goes to the merge worker's lane through `MergePiece`, the worker's next merge continuing its open segment, which needs the scheduler to hand each merge its worker number. The reserve holds one step per worker, and today `MergePiece` may open reserve segments with no limit and takes turns equally with the checkpoint's lane: a worker hands over its next step only once the manifest naming its previous one is durable, or, if review finds that obligation too easy to break, metadata lane 0 goes before merge lanes, or merge lanes leave a checkpoint's worth free, once only the reserve is free (raised in review of Metadata stream) ([The LSM tree](design.md#on-disk-format)). Review against the [LSM space spike](design.md#appendix-lsm-space-spike): at most one step plus a checkpoint's flush held beyond the manifests, every key reads the same before, between and after steps, across a crash between two steps, and a step finishes on a disk filled to its [reserve](design.md#on-disk-format). Prototype: `spikes/lsm-study-space/sim`.
- [ ] **Write admission** (component, `internal/disklog`, `internal/chunkstore`). Free segments outside the reserve against `clean_free`: a second cleaner worker at 14, chunk writes through a token bucket at the cleaner's measured net freeing rate (1 to 0.5×) at 8, ordinary items wait at 0; Raft entries, punches and freezes uncharged ([Writers slow down](design.md#on-disk-format)). Review in the simulator with the cleaner slower than the writers at 90 and 95% full: free segments outside the reserve stay above zero most of the time, no write fails while the cleaner has a victim, and write latency stays bounded.
- [x] **Durable LSN in record headers** (component, `internal/disklog`). The prelude carries the newest LSN durable when the round was built (56 bytes, so the one-header-block limit moves from 1,003 to 1,001 data blocks); the tail rule reports a gap that a whole header past it names durable, at any `commit_depth` ([Recovery](design.md#on-disk-format)). Golden bytes and the record codec and recovery scenarios in [test scenarios](test-scenarios.md) updated. Review when, at depth 2, damage in record 4 of 5 with round 5 begun after round 4 was durable gives Corrupt(4), while rounds 4 and 5 in flight together recover LSNs 1 to 3 (Pebble's `readAheadForCorruption` cases), and when a log written at depth 1 and opened at depth 2 with damage in record 4 of 5 gives Corrupt(4).
- [x] **Manifest edits and snapshots** (component, `internal/disklog`). A checkpoint writes an edit (runs added and removed, replay LSNs, the usage rows changed, from a bitmap of changed segments a failed checkpoint keeps) or a snapshot by Pebble's rule; the last piece lists the snapshot and edits; recovery applies them in order; every snapshot and edit records `NextSeq`, one past the open sequence of the newest segment a durable round had opened at the base LSN; the cleaner skips segments holding live manifest pieces and asks for an early snapshot ([The log is the source of truth](design.md#on-disk-format)). Review when open after any crash equals open from a snapshot taken at the same base LSN, and a usage table rebuilt from a snapshot plus edits equals the log's own.
- [x] **Checkpoint backpressure** (component, `internal/disklog`). Once ordinary records after the newest manifest, written or in flight, reach twice `max_replay_bytes`, rounds take only checkpoint and cleaner items until a manifest is durable, then the held items go out in submit order; the checkpoint's own records count toward replay but not toward the hold, and its pieces and manifest wait in a queue of their own, metadata lane 0, which merge output joins in skipping the hold ([The log is the source of truth](design.md#on-disk-format)). Review when a simulator seed with a stalled checkpoint keeps memtables under the bound; retained Raft entries join the check with Raft storage in the disk log.
- [x] **Held items** (component, `internal/disklog`). A round carrying checkpoint pieces and ordinary items adds to the hold its header blocks and every data block an ordinary entry's payload touches, so a piece's block counts only when it shares it with ordinary data, and recovery counts replayed records the same way ([The log is the source of truth](design.md#on-disk-format)). `Close` fails the items still waiting, for room or behind a checkpoint, with `ErrClosed` and the running checkpoint with `CheckpointFailed`, returning their buffers, and refuses only until format finishes and while a write or flush is in flight. Review when each rule fails under a planted bug.
- [x] **Reserve from settings** (component, `internal/disklog`). `Config` carries `merge_workers` and `compaction_step_bytes`, and the log sizes its reserve by `ReserveSegments` from them and the superblock's segment size at format and at every open, since a caller knows a disk's segment size only once recovery has read its superblock ([Free space](design.md#on-disk-format)). `Reserve` set directly replaces it and `NoReserve` asks for none by name (tests only), either of which makes `compaction_step_bytes` irrelevant, while `merge_workers` must still be in range since it sizes the lanes; both together are refused. Settings that name no reserve are refused before any disk action.
- [x] **Group commit API guards** (component, `internal/disklog`). `Submit` refuses a run piece (`BlobRun`) with `ErrReservedKind`, as it refuses manifests, so only `CheckpointPiece` and `MergePiece` write run pieces and the hold never counts an ordinary item as a checkpoint's or a merge's; tests' ordinary cold blobs use another kind. `Close` is `ErrBusy` until format's second flush completes.
- [x] **One `merge_workers` setting** (lib, `internal/lsm`, `internal/disklog`). `disklog.MergeWorkers` resolves the setting for both the log's `Config.MergeWorkers` and `lsm.SchedulerConfig.MergeWorkers`: 0 is `DefaultMergeWorkers` (1), below 0 or above `MaxMergeWorkers` (255, the lane byte) is `ErrBadConfig`, and the log needs it in range whether or not the reserve is set directly, since it also sizes the lanes. The daemon passes one value to both, so the reserve holds a step for every merge the scheduler runs.
- [x] **Metadata stream** (component, `internal/disklog`). A third stream for sorted runs, compaction output and manifests beside the hot and cold ones, filled in lanes: lane 0 of each stream is its shared segment, the checkpoint's queue is metadata lane 0, and merge worker *w* writes to lane *w* through `MergePiece`, one open segment at a time; byte 11 of the segment header names the lane, which only the metadata stream may set; group commit keeps a queue, a cursor and the append rule per lane, and rounds take the lanes with work in turn (hot, cold, metadata, merge lanes); `Submit` takes only the hot and cold streams, so an ordinary item never shares a segment with a checkpoint or a merge and the cold wait behind a checkpoint in the reserve is gone; replay reads each lane from its last segment whose first record is at or before the first to replay, merges every lane by LSN, counts merge lanes' records for the LSN chain, the tail rule and usage but delivers them to no index, and resumes each configured lane in its newest segment ([On-disk format](design.md#on-disk-format)). Golden bytes gain a metadata and a merge-lane header. Reviewed with planted bugs: per-stream replay, skipped merge lanes, merge records delivered, and merge lanes not resumed each fail a test.
- [ ] **Cleaner** (component). Cost-benefit victim choice with the net-gain guard and the age cap, copies into the cold stream, never a manifest piece, with live run pieces handled as the open question on [pieces shared between runs](design.md#roadmap-and-open-questions) settles, chunk blocks grouped by chunk into records of `copy` entries that name their source, a paced TRIM queue for freed segments (one `DiskTrim` per segment at `trim_rate`, faster only for a backlog older than 5 minutes, dropped when the segment is reused), and a second worker once free segments fall to 14. It takes live counts from the usage table and writes into the reserve when the disk is full, into a lane of its own in the cold stream so that ordinary cold items never append to a segment it opened from the reserve (group commit no longer tracks which open segment came from the reserve, since only the metadata stream could take one; raised in review of Metadata stream), and frees a used segment with no live block, such as one left empty by rounds recovery dropped, without copying anything. A segment it frees keeps its header of this log, and recovery judges it by the loaded manifest's `NextSeq`: a header below it is used only if the table lists it, one at or past it was opened after the manifest and its row comes from replay, and block 1 counts only a record at `NextSeq` or more. It lands with Manifest edits and snapshots' `NextSeq`. A freed segment may be reused at once, provided the cleaner frees nothing the newest manifest named by a durable segment header still needs (its pieces, the runs it names, the records after its replay points) and no replay LSN passes a copy record whose moves its index's runs do not hold; its TRIM is queued once a segment header naming the freeing manifest is durable, and allocating it drops a queued TRIM and waits for an issued one. It is its own state machine, which the daemon runs on a worker goroutine; its moves reach the index's owner as an event and apply only where a map still stores the copied blocks at that source, the test replay applies to a copy entry ([parallel cleaner spike](design.md#appendix-parallel-cleaner-spike), [value separation spike](design.md#appendix-value-separation-spike)). Review when the stale-header crash orders of the [log segments study](../studies/log-segments/) pass as its test scenarios, staged by the cleaner itself rather than by hand, and a pass finishes on a disk filled to its reserve, reporting no victim to group commit only when none passes the net-gain guard.
- [ ] **Chunk slots** (component, `internal/disklog`, `internal/chunkstore`). A chunk written whole in one write-back goes to a slot of a slot segment instead of the log, as many slots per segment as whole chunks fit, and none on a disk whose segments are smaller than a chunk ([Chunk slots](design.md#on-disk-format)). The round's record goes to the hot stream with a write entry 6 bytes longer naming the slot's segment and index, its per-block CRCs covering the slot's blocks; a slot segment has no segment header and is `slot` in the usage table; replay marks one opened after the manifest from the records naming its slots, never from its first block; a slot is free once the record that rewrote or deleted its chunk is durable, and the segment is TRIMmed and freed with its last slot; allocation fills the fullest slot segment first. Golden bytes updated. Review when a tail record's slot data is checked by recovery as log data is, a crash before the record is durable leaves the old chunk readable, and whole chunks deleted at random near the [cleaner streams spike](design.md#appendix-cleaner-streams-spike)'s 1.004 write amplification cost no cleaning.

**Simulator** (`internal/sim`; [Testing strategy](design.md#testing-strategy))

- [x] **Trace records** (lib, `internal/trace`). The fixed-field record of an event, an action, a syscall or an output, its one-line text form `tick loop kind fields...`, and the checker library that scans a trace for a rule such as one `DiskFsync` per round ([Testing the design decisions](design.md#testing-the-design-decisions)). Review when the simulator and a planted event-loop trace use the same checker.
- [x] **Deterministic scheduler** (component). One goroutine, simulated time, one seed. It schedules external actors as well as simulated nodes, so phase 5's event loops and worker jobs run on it as steps. Review when two runs of a seed produce byte-identical action traces.
- [x] **Simulated disk** (component). Torn writes, loss of unflushed data on crash, bit flips, misdirected writes, fail-slow, and injected errors by action kind, block range, action index and seeded probability: failed writes, failed flushes that leave unflushed blocks undecided, failed reads and reads with a changed byte ([Testing strategy](design.md#testing-strategy)). Review when a record written to the wrong address is never replayed there (recovery treats it as missing at its own place, by the tail rule), and a failed flush is never followed by an acknowledgment from the same open log.
- [ ] **Crash at every action** (test, `internal/disklog`, `internal/chunkstore`). A short workload with a checkpoint, a compaction and a cleaner pass, crashed at its k-th disk action for every k with none, a seeded half and all unflushed blocks landing, and separately failed at its k-th action; every recovery is a prefix of what was submitted and holds everything acknowledged, as Pebble's `TestErrors` and `TestDBCompactionCrash`.
- [x] **Crash oracle** (component, `internal/sim`). `sim.Oracle` keeps, per disk, every index's state at the last acknowledged LSN plus the records written since, generic over the record and a plain model; after a crash, a recovered LSN outside acknowledged to newest written is an error, and every index on the disk must equal the model with the records up to it applied ([Testing strategy](design.md#testing-strategy)). The disk log's harness hands it each round as its write goes out and each `Durable` LSN; the random-crash property, the failed-flush cases and the atomic-flush scenario check every recovery with it, and a recovery that stops an LSN early, one that replays past a gap and a checkpoint run missing the record at its replay LSN (RocksDB #11148) each trip it.
- [ ] **Chunk index under the crash oracle** (test, `internal/chunkstore`). The crash oracle checks only the disk log's block-map stand-in; the chunkstore tests' `node` runs the real `Index` over the log with crashes (`TestCrashBetweenRunAndManifest`) and compares it with a live index instead. Feed that node's rounds and `Durable` LSNs to `sim.Oracle` with a block model and compare the recovered `Index`, live and at every snapshot epoch, after each recovery, including one crashed part-way and run again, whose recovered LSN the oracle must see unchanged (raised in review of Crash oracle).
- [x] **Crash oracle hardening** (test, `internal/disklog`). The harness takes each segment's open sequence from the write that opened it, never from a header read back from the disk, and checks each durable record's decoded entries against the items submitted under its tickets, so a codec bug the oracle would share with replay, or a round that hands an entry out under another item's ticket (`disklog.SwapTickets`), fails. A seeded depth-2 and depth-3 workload tears an in-flight round with a whole one after it: recovery stops before it on every seed of 50, and `disklog.ReplayPastGaps` trips the oracle on every one.
- [x] **Every ticket resolves** (test, `internal/disklog`). When a watched log is dropped at a crash, and at the end of each watched test, every ticket submitted through the harness has ended `Durable`, `InDoubt` or `Failed`, or the log still holds its item queued or in a round in flight, and none is answered twice, so an item lost without an event from its queue or with its round in flight (`disklog.LoseNewest`, `disklog.LoseOldestRound`) fails. A round in flight at a crash that recovery keeps is checked against the items under its tickets as a durable one is, so `disklog.SwapTickets` in a kept round fails.
- [x] **Harness failures in scripted cases name their line** (test, `internal/disklog`). The scripted recovery case hands the harness a `testing.TB` that fails through the case's `d.Fatalf`, quoting the command running, so a harness check such as the ticket check names its testdata line; a case built in the test with `plant=swap-tickets` shows it.
- [ ] **Scripted cases that expect a harness failure** (test, `internal/disklog`). `plant=swap-tickets` fails any case it is in, so it lives only in a case the Go test builds by hand. A command such as `fails <text>` after a planted case's last line would let the testdata file show the ticket check catching it, as `index rejected` shows the oracle catching a recovery plant (raised in review of Harness failures in scripted cases name their line).
- [ ] **Invariant checker** (component). Phase 1 invariants: acknowledged writes are readable; no two writes of a chunk get one version; every read, live and at every snapshot epoch, equals a byte-range oracle of the acknowledged writes and punches applied in version order; punched ranges read zeros; every cleaner pass frees more segments than it fills; a cleaner move never replaces a write that landed during cleaning; no segment is reused while it holds a live block, or a piece, run or record after its replay points that the newest manifest named by a durable segment header needs; after every recovery the next open sequence number is at least the loaded manifest's `NextSeq`; a disk full except for its reserve still finishes a checkpoint, a merge step and a cleaner pass, and the bytes held beyond the manifests never exceed the reserve; no ordinary write fails with `NoSpace` while the cleaner has a victim; a rebuilt chunk index equals the one recovered from its manifest; a chunk's live map never holds two entries for one block, which with the record counts `chunkstore.(*Index).Check` verifies; a rebuild from record headers maps every copy entry exactly where the owner applied its move, record counts included.
- [x] **History recorder** (component). `sim.History` records each client operation as `(invoke_time, complete_time, op, result)` on the scheduler's time, an operation and its result as fixed arrays of words, allocating nothing per operation within the capacity it is made with; it converts to Porcupine's operations and back without loss, an operation that never completed returning at an infinite time and a client's pipelined operations overlapping under one client ID; `lincheck.Illegal` (`internal/sim/lincheck`) runs Porcupine and names, the same every run, an operation the longest legal prefixes leave out ([Consistency checking](design.md#testing-strategy)). Review with a register model: Porcupine accepts a linearizable history, rejects a stale read and names it, and lets an incomplete write take effect or not. Real-cluster histories are their own item in phase 5.
- [ ] **Seed runner in CI** (test). Thousands of seeds per commit; a failing seed prints a one-line replay command and its ops file reduced to the fewest ops that still fail, which becomes a data-driven regression case under `testdata/` before the fix. A change that adds a seeded test runs it over 10,000 seeds once.
- [x] **Data-driven files** (lib). `github.com/cockroachdb/datadriven` v1.0.2 for the metamorphic tests' regression cases, compaction picking (the universal picker cases ported from RocksDB's `compaction_picker_test.cc`), range-removal fragments and scripted recovery cases (a disk image built by writes, crashes and damage, then recovered), each command checked so a malformed line fails at its file and line.
- [x] **Recovery cases in one place** (test, `internal/disklog`). The scripted recovery file is the only home of the torn tail, middle and last-record damage and commit-depth-2 cases: its `index` command prints the last recovery's index as extents and whether every mapped block reads back.
- [x] **Scripted recovery checks a live model** (test, `internal/disklog`). The scripted recovery file runs the crash oracle: `index` prints each extent's pool and whether the index is what the oracle holds at the recovered LSN, naming the first block that differs, so a careless `go test -rewrite` cannot accept a wrong index unseen; `run plant=stop-early|past-gaps` shows the oracle catching a broken recovery.
- [x] **Scripted oracle mismatches fail** (test, `internal/disklog`). Each `index` in the scripted recovery file must match the crash oracle unless it is written `index rejected`, which must not, so `go test -rewrite` can neither accept a wrong index nor a plant or damage the oracle misses.
- [x] **Flush cadence counts absorbed writes** (test, `internal/sim/metamorphic`). A set's "flush after every n writes" counts the writes since the last flush began, those run between its pieces included, so writes between a flush's pieces never make a set skip one of its every-n flushes; the runner's tests check the cadence.
- [x] **Planted-bug check** (test, `internal/sim/toy`). The simulator replays a failing seed exactly and finds a bug planted in a toy primary-backup protocol whose messages the deterministic scheduler drops and reorders, ahead of phase 3's simulated network ([done-when checkpoint](design.md#learning-project), [planted bugs](design.md#testing-strategy)). Its client records its writes in a history, and the invariant, every acknowledged value durable on two disks, is checked after every step. Each of two planted bugs, an acknowledgment before any replica's and a reply taken across a primary restart, trips within the seeds every commit runs and replays to the same trace and step, and the fixed protocol passes them.
- [ ] **Client replies as outputs** (component, `internal/sim`, `internal/sim/toy`). The toy primary hands its acknowledgments to its client through a callback in its `Config`, since `core` has no output for a reply to a client (raised in review of Planted-bug check). Once the replica primary's client replies exist in phase 3, the toy emits the same output and the cluster completes its history from it, so the history recorder takes any machine's client operations without a hook.
- [ ] **Cleaner write amplification in simulation** (test). Uniform overwrites at 80 / 90 / 95% full land near the [cleaner spike](design.md#appendix-cleaner-write-amplification-spike)'s 3.4 / 7.2 / 17.3. With the chunk index's runs in the metadata stream, uniform overwrites land near the [cleaner streams spike](design.md#appendix-cleaner-streams-spike)'s 3.9 / 8.0 / 26 at 80 / 90 / 95%. Each disk's write amplification metric, which the [drive wear](design.md#volume-size-and-capacity) projection rests on, equals the run's measured figure.

## Phase 2: protocol models

- [ ] **TLA+ and TLC** (lib, `models`). Specifications in TLA+, checked with TLC 1.7.4, pinned with its [tech-debts](tech-debts.md) entry and using no CommunityModules operator that needs the 1.8 pre-release; etcd-raft's own specification (`tla/` in its repository) is the template. Each model has a `ci` configuration, exhaustive for safety and time-bounded liveness in under 5 minutes with 4 workers, run with its negative variants whenever `models/` or the TLC version changes; a `deep` configuration with one more node, chunk, crash or term and the unbounded liveness properties, run once per change to its spec, configuration or TLC version and capped at 4 hours; and a nightly TLC simulation run of about an hour with a fresh seed ([Testing strategy](design.md#testing-strategy)).
- [ ] **Epoch change model** (test, `models`). One spec with two `ci` configurations at 3 nodes, `ci-leases` (1 chunk, no merges, both clocks in full, every interval's members and activation) and `ci-peering` (2 PGs and 2 chunks, lease expiry left open within the order grants impose on peering), and a `deep` one holding both at 4 nodes. Two PGs sharing the nodes; tables carrying each PG's interval number, last activated interval and the members of the intervals since, adopted by nodes in order but possibly skipping some; messages tagged with a table epoch and an interval number, accepted only in the PG's current interval, with catch-up on a higher number; peering that reaches a member of every interval since the last activated one with at least `min_live` live members, reads members' missing lists and keeps every version below a kept one; a restarted primary taking a new interval; a chunk's counter running out ([Epoch changes](design.md#epoch-changes-and-failure-detection)). Per-node-pair read leases counted on two clocks per node, one slewed by up to ±22.6% or equal to the other (no daemon) and one drifting by up to ±4%, grants delayed by any amount and the holder's rate bound from any two grants of one grantor boot, no lease before the first bound, the step check at `1/(1 − m)`, and a grantor that reboots within `rate_window` with its raw clock restarted near 0 and its rate changed by 2%, with resumes from suspend and VM pauses that freeze a node's clocks, and Raft leader fortification on the same leases, with support epochs, the restart wait and leader transfer. Pending writes of a chunk, each merged on the version below it; connections as per-process channels carrying the incarnation in every chunk write and punch, and writes a primary holds across an interval change. Faults besides the study's: a replica replaced in an unactivated interval that keeps its primary, then a primary move, while the old primary serves reads under the new replica's grant; a primary holding a client write that pauses past `node_down_after`, skips the tables in which another primary led the PG and leads it again; and a member's disk formatted again, its log emptied and its log ID new. Counterexamples to find: a disk ID kept across a new log ID, peering that reaches only the last activated interval and the current one, incarnations checked only when a write arrives, held writes ordered again after another primary led the PG, a member that logs one version out of order, a new primary that merges before it holds a kept version, peering that stops only the previous interval, comparing member lists instead of interval numbers, a restarted primary peering in its old interval, deciding an older version by its own interval's members after a later interval kept it, and activating before missing lists are durable; for leases, a lease on `lease_drift` alone before the first bound, that with the step check at `1 + lease_drift / 2` restarting the window on each trip (a grantor 1.2% fast never gets a bound), widening only past `1 + 2 lease_drift`, the margin `max(lease_drift, 1 − 1/B)` with a raw rate step of 0.4% after measurement, and a window not restarted at a grantor's new boot. Properties: no PG serves reads from two primaries at once; no two replicas of a shard serve lease reads at once; no write tagged with an interval completes after a later interval of its PG activates; no acknowledged version, and no version an activated interval kept, is ever dropped; the versions peering drops are a suffix of each chunk's pending versions, so no kept version was merged on a dropped one; no two writes of a chunk get one version; a table that leaves a PG's interval alone never fails its writes; a new primary merges into a chunk only once it holds every version peering kept; table epochs and interval numbers never go backwards; once a reissue and a later write to the same block are acknowledged, the block never again holds the dead daemon's write; and, as an invariant over the model's clocks, a pair whose raw rates differ by up to 4% holds a lease within `rate_gap` plus two round trips of first contact and keeps it with no detections ([lease margins study](../studies/lease-margins/README.md)). The [PG epochs study](../studies/pg-epochs/README.md) lists the faults.
- [ ] **Sessions and fencing model** (test, `models`). Renewal on heartbeats to the control-plane leader, expiry on the leader's clock, a full lease after a leader failover, the client's rate bound kept per leader node and boot and its step check at `1/(1 − m)`, fences batched into session-table versions, acknowledgments from every storage node and the acknowledged version that releases owners ([Sessions and fencing](design.md#sessions-and-fencing)). Properties: no fence commits while the client's own lease still runs; no fenced session's write is applied; no lock reaches a new holder while a primary would still accept the old holder's writes.
- [ ] **Cache-mode recall model** (test, `models`). Lost and delayed recalls, a client paused past its lease, owner failover mid-recall. Property: no stale read in WriteShared mode.
- [ ] **Purge model** (test, `models`). Two inodes in one slot's purge list. Crash mid-purge, unlink racing a write, truncate to an unaligned size followed by extend, a crash between a truncate's transaction and its punch of the partial block, a truncate then an unlink before the purge runs, two truncates, an unlink of a lower inode between the purger's scan and its range removal. Properties: an interrupted purge reruns safely; a purge never deletes newer data; once a file's purge has run, no byte past its size is non-zero, and an extension never exposes one.
- [ ] **Model-to-simulator map** (test). Each configuration states its constants, depth, distinct states and wall time, and each property names the simulator invariant that checks it in the real code.

## Phase 3: replication and placement

The control-plane Raft group arrives in phase 4, so here a simulated single authority stands in for it.

- [ ] **Wire messages** (lib, `internal/chunkstore`). Hand-written encodings with a version. From the start, every message about a PG carries the sender's table epoch and the PG's interval number, and a client chunk write and punch its session ID, its incarnation and its byte range with the whole-block data at block-aligned offsets of the frame, so the receiver lands them in aligned pool buffers without a copy.
- [ ] **Pools** (component, `internal/chunkstore`). Settings and creation rules for 1 to 3 copies and `min_live` ([Pools and redundancy](design.md#pools-and-redundancy)); erasure coding waits for phase 10. Capacity figures from member fills, each pool's data per disk and the table ([Volume size and capacity](design.md#volume-size-and-capacity)): available (the smallest room ÷ share, less outstanding grants), and over each failure domain's capacity, room plus the pool's own data, balanced (min over j of S₍>ⱼ₎ ÷ (b − j·a), a = 1 for copies), the stranded fraction with each domain's stranded room, and reprotectable over the losses the design lists; the `Full`, `NearFull`, `Stranded` (against the confirmed fraction), `Unbalanced` (evaluated only once placement has stopped), `CannotReprotect` and `Stuck` conditions with their clearing rules, in whole blocks; and reservations for `overcommit` off against balanced. Review with the [capacity model spike](design.md#appendix-capacity-model-spike)'s C1 to C6 as data-driven cases: the figures match its results and the conditions the [capacity conditions study](../studies/capacity-conditions/README.md)'s outcomes, and property tests show available + held ≤ balanced ≤ Σ capacity ÷ b and a stranded fraction that does not change as a pool fills.
- [ ] **Placement computation** (component, `internal/chunkstore`). Refill every missing member (its disk left the pool or lost its log, or it has been down for `refill_after`, or for `degraded_refill_after` in a PG below `min_live`, and peering does not wait for it anyway; a member merely down stays; a refill member counts toward `min_live` while it recovers), then balance from the disk furthest above its target while any disk is outside its fill margin of max(5% of target, 1 member), under the failure-domain rule, toward each disk's capacity for the pool, water-filled over domains with at most `max_per_domain` of a PG's width each, stopping when no move helps ([placement table](design.md#data-layer-chunkstore)). Each PG entry carries its interval number, raised exactly when the PG's ordered members, a member's live mark, its pool's `replicas` or `min_live`, or a split change it, or its primary asks, both halves of a split PG starting one above it; each table is also a delta of the entries it changed with the resulting table's CRC32C. Review with property tests: after any add, remove and failure sequence, every PG keeps its width with at most `max_per_domain` per domain, no table raises an interval it need not, a member removed and added back gets a new interval, a delta applied to the previous table reproduces the whole table and its CRC, after a disk is added to a pool holding data the second computation proposes no move, the loop converges with every disk within its margin, available + held is then at least balanced ÷ (1 + the largest margin), and moves stay near the minimum.
- [ ] **Replica primary** (component, `internal/chunkstore`). Parallel fan-out, commit once every live member holds the version, a write mapped into the index only once it commits and a chunk's writes in version order, a dropped version superseded in the log of every member that logged it, the primary included, a chunk's writes sent to every member in version order and again in that order after a reconnect, partial blocks merged against pending versions with the merged whole blocks sent to the replicas and a per-loop cache of recently merged blocks, a base that fails its CRC32C fetched from another member before merging, reads of committed versions only, versions numbered from the PG's interval with a counter per chunk, a new interval asked for when a chunk's counter runs out, messages accepted only in the PG's current interval and client writes only within the primary's term, a client write's incarnation checked when it is ordered, held writes ordered again after re-peering only if no other primary led the PG since, tables applied as deltas and fetched whole after a gap or a CRC mismatch, `min_live` and `maintenance`, and `write_limit` admission from the fill each member reports and the pool's outstanding grants from the leader's heartbeat reply: a write that adds live data past it is refused with `NoSpace`, while granted flushes, overwrites of blocks held live, unshared and as copies with no freeze due, and punches are admitted ([Volume size and capacity](design.md#volume-size-and-capacity)).
- [ ] **Peering and read leases** (component, `internal/chunkstore`). As modeled in phase 2 (the epoch change model's `ci-leases` and `ci-peering` configurations), leases renewed by node-pair heartbeats, in `internal/lease`: grants carry a support epoch bumped on lapse, a restarted node grants no vote or peering until both its clocks show one `primary_lease`, a lease is counted on `CLOCK_BOOTTIME` and `CLOCK_MONOTONIC_RAW` with the holder ending it `lease_drift` early on the faster and the grantor on the slower, a holder ends its leases on `Resumed` and when a grantor's `CLOCK_MONOTONIC_RAW`, carried on every heartbeat, moved more than `1/(1 − m)` times its own since the last grant, `m` that lease's margin, handling peer messages before reads, then asks again at once and restarts its rate window, and a holder bounds each grantor's rate, per grantor node and boot ID carried on every grant and heartbeat, from the send and receive times of the shortest-round-trip grants in the first and last thirds of its window, asks again `rate_gap` after a window's first grant, takes no lease from a grantor before it has a bound, widens its margin by the bound's excess over `1 + lease_drift / 2` and takes no lease at `max_margin`; peering reaches a member of every interval since the PG's last activated one that had at least `min_live` live members, members persist their missing lists before the primary activates and never serve a chunk on them, a version of the last activated interval is dropped only when a member live in it neither holds nor lists it, every version below a kept one is kept, which drops only a suffix of each chunk's pending versions, a chunk whose kept version no reachable member holds is reported unfound, divergent members are recovered by copying from the authoritative one, and a partial-block write to a chunk waits until the new primary holds every version peering kept for it ([Epoch changes](design.md#epoch-changes-and-failure-detection)); review with the spike's M6 to M8 as simulator seeds. A restarted primary takes a new interval of each PG it leads and peers in it before it serves; a primary reports activation on its heartbeat. Each disk is known by the log ID it reports: a log ID the authority does not know joins as a new disk under a new disk ID, the disk ID it replaced stays down, and a log ID already up is refused.
- [ ] **Failure and fail-slow detection** (component, `internal/chunkstore`). Node heartbeats and `node_down_after`; each disk's oldest unfinished read, write or flush aged on its owner loop and carried on every heartbeat, discards left out; `member_timeout` reports answered by a direct probe to the disk's owner loop, answered from memory; a disk stalled past `member_timeout`, or whose log failed, or whose loop does not answer, marked down at once, `min_live` or not ([Hung disks](design.md#epoch-changes-and-failure-detection)); fail-slow marking guarded by `min_live`; rejoin after either only once a whole `slow_disk_window` passes normal and with no stall; a node or disk marked down `flap_count` (5) times within `flap_window` (10 minutes) held down until a whole `flap_window` passes normal, unless a PG it belongs to would stay below `min_live` with no eligible disk to refill onto; when each member was marked down, which placement compares with `refill_after` and `degraded_refill_after` ([Failure detection](design.md#epoch-changes-and-failure-detection)); and, on a new control-plane leader, the `node_down_after` count started from its leader lease.
- [ ] **Recovery per PG** (component, `internal/chunkstore`). Most-degraded PGs first; resync after maintenance or an outage shorter than `refill_after`, copying only the versions on the returning member's missing list.
- [ ] **Simulated network** (component, `internal/sim`). Drop, delay, reorder, duplicate, partition; node crash and restart; per-node clock drift, time-daemon slews, suspends and VM pauses that freeze a node's clocks, with the messages sent to it queued or lost. Its per-node clock model can be imported alone, by `internal/loop/looptest`, and it delivers `Resumed` through `core.Resumed`.
- [ ] **Placement faults and invariants** (test, `internal/sim`). The placement faults listed in [Testing strategy](design.md#testing-strategy), checked against: one read-serving primary per PG; no read returns a version before it commits; no write after a later interval of its PG, and none refused for its interval while its PG's interval did not change; no acknowledged version, and no version an activated interval kept, is ever dropped, and no kept version follows a dropped version of its chunk; no two members hold different data under one version; no node's table epoch or PG interval number goes backwards; every chunk reaches its pool's copy count once recovery settles; too few copies return an error, never wrong data; a disk passes `write_limit` only through granted flushes, overwrites, punches and recovery; uniformly hashed fills reach the reported available figure within 1%.
- [ ] **Consistency check of chunk histories** (test). Porcupine finds a linearizable order per chunk for recorded simulation histories. A write resent after its first attempt committed counts as one write or as two by the answer to the open question on [resent chunk writes](design.md#roadmap-and-open-questions).

## Phase 4: embedded MetaStore

- [ ] **etcd-raft module** (lib). `go.etcd.io/raft/v3` v3.6.0 through a `replace` to a pinned fork that gives each replica a seeded election-timeout source in place of `crypto/rand` and carries v3.7.0's ReadIndex retry fix (etcd-io/raft#397) ([Raft shard](design.md#metadata-layer-metastore)). The pin and the patches go into `docs/tech-debts.md`; the pin is removed when an etcd-raft release keeps messages and entries without per-field allocations, measured at no more than 3 allocations per message by `spikes/raft-rounds`. Review when a simulator seed replayed twice gives identical histories.
- [ ] **Upstream Raft tests** (test). etcd-raft's own unit tests and datadriven testdata pass on the patched fork, rerun on every upstream tag update.
- [ ] **Raft shard** (component, `internal/raftshard`). Wraps `raft.RawNode` in `OnEvent`: ticks from `ctx.Now`, messages from `NetRecv`, payloads over 256 bytes as `IOBuf`s. Synchronous `Ready`/`Advance`, a 10 ms election tick under a 100 ms heartbeat; a leader's appends go out with its own write, and every other message of a `Ready`, a vote included, waits for the round's flush, a pre-vote excepted ([Raft shard](design.md#metadata-layer-metastore)).
- [ ] **Leader leases** (component, `internal/raftshard`). Fortification on the per-node-pair leases. While a follower supports a leader, it drops its group's (pre-)votes, except a transfer's, and its election timer stays stopped. The lease is the quorum-th expiry over fortified voters, per half of a joint configuration. Reads go through ReadIndex until the leader is fortified, holds a quorum of expiries, each needing a rate bound for that voter's node, and an entry of its term has committed. The lease ends when `MsgTimeoutNow` leaves. `CheckQuorum` is off and `PreVote` on. A follower whose fortification ends with its grant campaigns, pre-vote first, after a random `raft_lapse_campaign` (150 to 300 ms), and after a failed pre-vote at its election timeout ([Metadata layer](design.md#metadata-layer-metastore)). Review with tests: a supporting follower drops a challenger's pre-vote and vote but passes a transfer's campaign, and votes once its grant lapses; a follower whose grant lapses campaigns within 300 ms, not at its election timeout; a 3-voter group with one of two followers fortified holds a lease to that follower's expiry; a joint configuration needs a quorum in each half; a restarted node refuses votes for `primary_lease`; a holder that receives `Resumed` stops serving; a lapsed epoch's renewal is refused.
- [ ] **Voter replacement** (component, `internal/raftshard`, `internal/meta`). The control-plane leader places each group's three voters, one per metadata node, on the disk of that node with the fewest shard replicas, recorded in the shard map under `ctl/`; it replaces a voter down for `refill_after`, or at once when its disk's log is gone, through the group's leader: the new replica joins as a learner, catches up from the log or a snapshot taken from a point-in-time view, and one `ConfChangeV2` removes the dead voter and promotes it through a joint configuration; the control-plane group does the same for its own voters ([Replica placement and replacement](design.md#metadata-layer-metastore)). Review with tests: no learner is promoted before it has caught up with the leader's log; a replacement while one voter is down commits with the two survivors and never stalls proposals; a removed replica whose node returns deletes its state; on three metadata nodes a voter whose node is down is not replaced, and one whose disk lost its log moves to another disk of its node.
- [ ] **Raft storage in the disk log** (component, `internal/raftshard`). Entries and hard state join the round's record. `raft.Storage` serves every entry after the last compaction from the loop's off-heap slab; the log compacts, and its entries become dead to the cleaner, once the memtable that applied them is flushed.
- [ ] **Raft cost per group** (test). A regression benchmark at 1,000 groups per node: at most 3 allocations per message and at most 4 KiB of heap per idle group on the pinned version, against the [raft rounds spike](design.md#appendix-raft-rounds-spike)'s 2.7 and 2.8 KiB.
- [ ] **Maelstrom harness** (test). A small I/O adapter that runs the Raft shard as a Maelstrom node; passes the linearizable key-value workload under partitions ([done-when checkpoint](design.md#learning-project)).
- [ ] **Shard state machine** (component, `internal/meta`). `Txn` with `Put`, `Delete`, `DeleteRange`, `Check`, `CheckEmpty` and `Update` (`Set`, `Add`, `Bump`), evaluated at apply time, checks against the state before the `Txn` and then writes in list order, all or nothing, a failed check returning its index and its key's value; replay records storing only final results and dropped below a mount's oldest outstanding request and at session end; limits checked before proposing (`max_txn_bytes` 256 KiB, `MaxKey`, `MaxValue`, range bounds of at most 1,000 bytes, at least one op); `Scan(start, end, limit)` over `[start, end)` with a byte budget (`max_scan_bytes` 256 KiB) and `more`, on the LSM tree, with one log entry per leader per round ([Metadata layer](design.md#metadata-layer-metastore)).
- [ ] **Key encoding** (lib, `internal/meta`). The design's one-byte tags, fixed-width big-endian integers (session and request IDs 64 bits, mount IDs 32), a variable last component, and piece keys for values over 1,000 bytes; keys at most `MaxKey` (1,032 bytes, raised from 1,024 by the Range removals item). Review with golden vectors (the tags, the 34-byte replay key, piece keys), a property test that byte order equals logical order, and a fuzz test of the key and piece decoders.
- [ ] **Sharded API, one shard** (component, `internal/meta`). Routing through the shard map and the single-shard fast path, with `ctl/` pinned to the control-plane group; a follower answers `NotLeader` with the leader's node and term, never forwarding (`DisableProposalForwarding`), and the daemon's route cache resends; a `Txn` whose keys span two Raft groups, the control-plane group included, is refused with `ErrCrossShard` naming them until phase 13 designs and models cross-shard transactions.
- [ ] **Control-plane group** (component, `internal/meta`). Pools, placement table (committed as deltas with the resulting table's CRC32C, each PG with its interval, last activated interval and the members of the intervals since, activation reports folded in from heartbeats), membership, sessions (renewed in the leader's memory, expired and fenced by the leader, with the session table and its acknowledged version), space grants per node and pool on the session heartbeat (asks from buffered plus flushed bytes, at most half of available, divided by water-filling with buffered floors and no reuse above the level; Σ (1 + k) × grants + F within every disk's gap above the larger of its fill and `write_limit`, each node counted at max(held, new) until a heartbeat echoes its grant; cumulative flush counts; every live session counted at (1 + k) × `writeback_buffer` after a leader failover, and a lapsed session's grant until its fence is acknowledged; [Client design](design.md#client-design)), format level and shard map under `ctl/`, replacing phase 3's stand-in.
- [ ] **Filesystem schema** (component, `internal/meta`). Inode numbers reserved 64 at a time and slots 16 at a time by `Txn`s of their own and prefetched, a `mkdir` in a fresh slot taking sequence 1 and handing its daemon 2 … 65; inodes with fixed-layout attributes, directory entries, parent pointers, xattrs and symlink targets in pieces past 1,000 bytes, locks keyed by mode, orphans, one merged purge entry per inode whose truncate ranges start at the new size's byte offset, slot byte counters by `Update`, replay records keyed by session, mount and request; each operation's ops as the design's transaction table gives them, the parent's times by `Bump` ([Key layout](design.md#metadata-layer-metastore)).
- [ ] **MetaStore invariants** (test, `internal/sim`). At most one leader per shard per term; no two replicas of a shard serve lease reads at overlapping times; a committed entry is never lost; a shard recovered from manifest and log equals its state before the crash; at most one lock holder; no session is fenced while its client's own lease still runs, and no lock reaches a new holder while a primary would still accept the fenced holder's writes; on every disk of a pool (1 + k) times the grants outstanding plus the flushes not yet in fill reports never exceed its gap above the larger of its fill and `write_limit`, and no flush under a grant is refused for space; a replayed request returns its first final result and changes nothing, and an internal `Txn` repeated after an election changes nothing it did not read; no learner is promoted to voter before it has caught up with its leader's log.

## Phase 5: default drivers

- [ ] **Off-heap slabs** (component, `internal/loop`). Slabs mapped with `unix.Mmap`, page-aligned, handed out as slot and generation handles; the buffer pool and the memtable's page store on top ([Runtime in Go](design.md#runtime-in-go)). Review when a stale handle is caught and the Go heap stays flat while slabs fill.
- [ ] **Event loop** (component, `internal/loop`). One epoll loop goroutine per core over every driver's readiness fd, on raw non-blocking descriptors; executes actions, feeds events. An inbox of a lock-free queue and an eventfd, a timer heap on one timerfd, loops and `GOMAXPROCS` sized from the cgroup CPU limit (Go's default − 1 loops under a limit; one per CPU plus an extra P without), `RawSyscall` for non-blocking I/O, `writev` once per descriptor per pass, a read budget per descriptor per pass and capped replication queues ([Runtime in Go](design.md#runtime-in-go)). Every syscall the loop makes goes through a recording layer that emits a trace record. Waiting, the clock reads and timer arming go through the kernel seam, with the clocks read after the wait; `Pass` and `Pending` are exposed, and `looptest` steps many loops from `internal/sim`'s scheduler on scripted clocks; `tools/sansio`'s loop rule set passes ([Testing strategy](design.md#testing-strategy)). Review when a seeded stepped run of 8 loops over socketpairs gives the same results and per-loop event order twice, and a loop that would block with work pending fails the stepped run; on the real kernel the trace of a pass under 1,000 connections shows one `epoll_wait`, at most one `writev` per ready descriptor and no more than the read budget per descriptor; `runtime.NumGoroutine` is the same with 1 and 1,000 connections; under a 2.5-CPU cgroup the daemon runs 2 loops with `GOMAXPROCS` 3 and `cpu.stat` shows no throttling at idle; `testing.AllocsPerRun` of a pass is 0; and with the [open-loop latency spike](design.md#appendix-open-loop-latency-spike)'s load generator no request is dropped up to the offered rate the spike's harness served ([Testing the design decisions](design.md#testing-the-design-decisions)).
- [ ] **Clock and timers** (component, `internal/loop`). `CLOCK_BOOTTIME` to `ctx.Now` and `CLOCK_MONOTONIC_RAW` to `ctx.Raw`, read together each pass, and a `Resumed` event when `CLOCK_BOOTTIME` gains on `CLOCK_MONOTONIC` or the VMClock disruption marker, read from a mapped `/dev/vmclock0` where present, changes ([Epoch changes](design.md#epoch-changes-and-failure-detection)); `SetTimer` on the loop's timer heap and a timerfd on `CLOCK_BOOTTIME`. Tested on scripted clocks through the kernel seam; the `Resumed` detector and timer heap are pure functions in `internal/core`. Review when every Clock and timers scenario passes stepped, the real-kernel checks pass in CI, and the VMClock rows pass nightly in the VM pause harness.
- [ ] **io_uring disk driver** (component, `internal/driver/uring`). Its own ring over raw syscalls, its completion eventfd in the loop's epoll set. File or raw device, `O_DIRECT`, vectored writes, a write and its `IORING_FSYNC_DATASYNC` linked in one submission, `durability: fua` as a setting, file-backed segments written in full at creation, discard for freed segments, zeroing the header instead where a discard does not read back as zeros. The loop's slab registered as fixed buffers (regions of at most 1 GiB) and its disk descriptors as fixed files, with a fallback to plain `READ`/`WRITE` when registration fails (`ENOMEM` under the memory-lock limit), reported in the driver's status ([Runtime in Go](design.md#runtime-in-go)). Event mode only, never waiting in `io_uring_enter`. Building submission entries from actions and decoding completions into `DiskDone` are pure functions with table tests and fuzzing; the ring itself is tested on the real kernel with a file-backed disk, natively or in a container that allows `io_uring_*`. Formatting a raw device discards every segment, or zeroes each segment header where a discard does not read back as zeros, so a header left by the device's earlier use never makes recovery read that segment in full at every start.
- [ ] **TCP network driver** (component, `internal/driver/tcp`). One connection per pair of event loops, opened on demand and chosen by the owner map ([Runtime in Go](design.md#runtime-in-go)), framing, messages batched per connection, `PeerLost` on any transport error, reconnect. Dial and listen are passed in, so tests can use socketpairs; transport errors are produced on loopback (a reset, an EOF, a reader that stops).
- [ ] **Round driver** (component, `internal/loop`). Collects the `Ready` of the shards marked since the last round, and the chunk writes, once per round, bounded by `max_group_commit_bytes` only. Each loop hands its records for a disk to the disk's owner loop in one inbox message per pass and gets one durable notice per round back ([On-disk format](design.md#on-disk-format)). Review with a stepped trace check, with 1, 2, 4 and 8 producer loops: at most one inbox message per producer loop per disk per round in each direction, and one `DiskFsync` per round per disk whatever the number of producer loops; records from 8 producer loops land in one record; a shard's replayed entries and the cleaner's moves for its runs reach the shard's loop. A round with 1,000 idle shards and one active shard calls `HasReady` on one shard, and a pass's CPU with 1,000 idle shards does not depend on the shard count; a round that reaches `max_group_commit_bytes` leaves the rest for the next round in order, and every shard is collected within two rounds. Measure commit latency p50 and p99, on real loop goroutines, against the [raft rounds spike](design.md#appendix-raft-rounds-spike)'s 3 and 5 ms at a 0.95 ms flush.
- [ ] **Shared ChunkStore suite** (test). One suite, run on the simulated disk and on io_uring ([done-when checkpoint](design.md#learning-project)).
- [ ] **Shared network suite** (test). One suite, run on the simulated network and on TCP, ready for RDMA in phase 9.
- [ ] **Durable write benchmark** (test). 4K at queue depth 1 with idle gaps, against the [NVMe flush spike](design.md#appendix-nvme-flush-spike)'s floor of about 0.95 ms (2 ms after idling), cross-checked with fio. Report CPU per write and the recovery time of a full disk's segment headers.
- [ ] **Crash tests on real disks** (test). `kill -9` mid-round, and device-mapper error and delay targets where root is available; the test driver keeps the crash oracle in a file outside the daemon, as RocksDB's crash test keeps its expected state and trace, and every restart recovers a prefix holding every acknowledged write.
- [ ] **Real-cluster histories** (test). The crash test driver, and later the file tests of phase 6, record every client operation in the history recorder's format, from clients on several nodes, so the same Porcupine check reads them; recording allocates nothing per operation on the data path. Settles the open question on [real-cluster histories](design.md#roadmap-and-open-questions) first: the time base and where a run's history is written.
